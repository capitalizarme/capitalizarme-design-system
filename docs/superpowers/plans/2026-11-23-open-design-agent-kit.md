# Open Design Agent Kit Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make this package consumable by open-design-agent-kit: a generated, self-contained `tokens.css`, a kit-schema `brand.json`, and integration docs.

**Architecture:** `scripts/build-tokens.mjs` parses the first top-level `:root` block of `colors_and_type.css`, overrides `--focus-ring` in place, appends the kit-contract tokens the source lacks, and writes `tokens.css`; `--check` compares instead of writing. `brand.json` is edited in place. Docs are Markdown.

**Tech Stack:** Node 24 (ESM, `node:fs`, `node:test`, `node:assert`). No npm dependencies.

**Spec:** `docs/superpowers/specs/2026-11-23-open-design-agent-kit-design.md`

## Global Constraints

- Never rename or behaviourally change `colors_and_type.css`; it stays the token source of truth.
- `tokens.css` is generated only; it starts with a `/* GENERATED by scripts/build-tokens.mjs from colors_and_type.css — do not edit */` header.
- `tokens.css` contains exactly one `:root { … }` block, no `@import`, and every `var(--x)` it references is declared in that block.
- All 56 `KIT_TOKENS` names (Task 1) are declared in `tokens.css`.
- Contract-token values are exactly the spec's mapping table; no other values invented.
- `brand.json` keeps every existing key and mascot entry; adds `version: 1`, `kind: "own"`.
- No new dependencies; `package.json` gains scripts only (plus `files` entries and version).
- Release bump: MINOR → `0.8.0`.

## Review Focus

1. Comments inside `:root` containing `;`, `:` or `--` (e.g. `/* ... 4.76:1 ... */`) — must not be parsed as declarations or split values. Test: `parseRootDeclarations` on a fixture with such comments.
2. Values containing `;`-free but `,`/`(`-heavy content (`color-mix(...)`, multi-shadow, font stacks with quotes) — must survive verbatim. Test: fixture asserts exact `--shadow-sm` and `--font-display` strings.
3. A second `:root` / declarations inside `@media` later in the file — only the first top-level `:root` is read. Test: fixture with a later `@media { :root { --bg: red } }` keeps `--bg` from the first block.
4. `--focus-ring` appearing twice in output — must be replaced in place, once. Test: count of `--focus-ring:` in output === 1.
5. `--check` when `tokens.css` is missing or stale — must exit non-zero with a message naming `npm run build:tokens`. Test: `checkTokens` returns `{ ok: false }` for missing and for differing content.

- Produces (named exports of `scripts/build-tokens.mjs`):
  - `KIT_TOKENS: readonly string[]` — the 56 names below.
  - `CONTRACT_ADDITIONS: Readonly<Record<string,string>>` — the mapping table below.
  - `FOCUS_RING_OVERRIDE: string` = `"0 0 0 2px var(--bg), 0 0 0 4px var(--color-brand-blue)"`

  - `checkTokens(sourceCss: string, currentTokensCss: string | undefined): { ok: boolean, message: string }`
  - CLI: `node scripts/build-tokens.mjs` writes `tokens.css` (paths relative to repo root via `import.meta.url`); `--check` prints `message` and exits 1 when `!ok`.
- `package.json` scripts: `"build:tokens": "node scripts/build-tokens.mjs"`, `"check:tokens": "node scripts/build-tokens.mjs --check"`, `"test": "node --test scripts/"`.
